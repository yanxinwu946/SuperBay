# 启动、终端与 Scoop

工具找到之后，怎么启动往往才是麻烦的部分：脚本要用哪个解释器、命令行工具该在哪个终端里跑、多个版本怎么共存。这份文档讲清楚这三件事。

[项目说明](../README.md) · [使用说明](user-guide.md) · [目录规划指南](directory-planning.md)

## 启动入口

选中工具后，右侧详情会列出识别到的启动入口。存在多个候选时可以点击「切换」，选择会被记住；自定义命令留空时继续自动识别。

- **桌面程序**直接打开。
- **命令行程序和脚本**可以交给外部终端，在可见的窗口里运行。
- `Ctrl+Enter` 以管理员权限启动；也可以在「启动命令与标签」里固定为「总是以管理员身份启动」。
- `Shift+Enter` 带参数启动，每次运行前填写。

## 外部终端

打开「设置 → 启动 → 外部终端」：

- **终端程序**留空时会自动适配 WezTerm、Windows Terminal 和 Alacritty；也可以浏览选择一个自定义程序。
- **自定义参数**支持 `{cwd}` 和 `{command}`，必须包含 `{command}`，否则保存时会提示。
- 脚本执行方式可以在「使用 PowerShell」和「使用 Windows 控制台」之间选择。
- 配好后点「试开终端」验证，不必回到列表里试错。

## 启动方案

同一个工具常有几种用法：带不同参数、跑不同子命令、连接不同环境。把这些保存成启动方案，比每次手动输入更省事。

每个方案包含名称、命令和启动参数。参数里可以使用占位符，运行时再填具体值：

| 占位符 | 含义 |
| --- | --- |
| `{参数}` | 运行时输入的任意参数 |
| `{文件:file}` | 运行时通过文件选择器选取的文件 |
| `{目录:dir}` | 运行时通过文件夹选择器选取的目录 |

方案名称不能重复；保存后可在工具详情里直接选用。

## 运行环境

「运行环境」用于给工具绑定 Scoop 中的具体版本，适合需要固定 Python、Node.js 或 Java 版本的工具。

- 填写 `包名/版本` 格式，例如某个 Python 版本；留空则使用系统环境。
- 绑定后，启动该工具时使用对应解释器或运行时，不影响其他工具。
- 已安装的 Scoop 版本可以在 Scoop 管理中查看，也可以在那边直接「绑定到条目」。

## Python 后端

适合本地服务、脚本工具这类需要长期运行、又不想留一个黑窗口的程序。

在工具详情中打开「Python 后端」：

- 无窗口启动 Python 脚本或模块，例如 `python -m uvicorn app:app`；
- 需要明确的 Python 入口或已配置的解释器，识别不到时会提示；
- 运行输出可以随时查看，排查启动失败很方便；
- 在 SuperBay 本次运行期间可以停止该进程，退出程序时也会一并结束。

后台运行只覆盖 SuperBay 的生命周期。需要开机常驻的服务，请单独配置系统服务或计划任务。

## Scoop 管理

从顶栏或设置进入「Scoop 管理」。首次使用可以连接已有安装，或直接安装 xrgzs/scoop；也可以在设置里指定 Scoop 安装目录。

**浏览与筛选**

- 「全部软件」「所有版本」「已安装」三个视角切换；
- 按名称、版本或来源搜索，已安装列表可以筛选 Python、Node.js 和 Java；
- 默认显示当前版本，切到「所有版本」查看历史版本。

**批量操作**

勾选软件后可以批量更新、冻结、解冻、切换版本、清理历史版本和卸载。搜索结果支持批量安装，更新检查的结果支持「更新所选项」。

- 清理历史版本会保留当前版本；
- 卸载会保留持久化数据，配置和缓存不会一起消失。

**软件源与设置**

可以添加、删除和切换软件源，调整 Scoop 自身的设置。所有操作都有输出日志，执行完成后即可关闭面板，不必盯着进度。

## 数据

设置和工具元数据保存在本机，笔记保存在对应工具目录。路径、迁移步骤和「清理失效记录」的说明见[使用说明 · 数据与迁移](user-guide.md#数据与迁移)。
