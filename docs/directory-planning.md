# 目录规划指南

SuperBay 不要求你把工具搬到新地方，但目录怎么摆，直接决定之后找东西顺不顺手。这份指南写给两类读者：准备整理工具目录的用户，以及帮用户做规划的 AI。

[项目说明](../README.md) · [使用说明](user-guide.md) · [启动、终端与 Scoop](toolbox-features.md)

## 结构模型

只有三层需要记住：

```text
D:\Tools\                    工作区：存放分类的那一层
├── A-01-图像处理\           分类：一级目录，可再嵌套子分类
│   ├── ImageTool\           工具：一个完整文件夹
│   │   └── ImageTool.exe
│   └── 批处理脚本\
│       └── convert.py
└── B-02-视频处理\
    └── VideoTool\
```

- **工作区**：扫描入口，选到工具内部会导致识别不到东西。
- **分类**：侧栏的导航单位，嵌套层数不限，但越浅越容易找。
- **工具**：保留完整目录，脚本、配置、输出都放在里面，扫描时不会被拆散。

## 命名规范

分类用 `A-01` 或 `A-01-名称` 命名：

- 字母和编号让排序稳定，不受中文拼音或修改时间影响；
- 名称按自己的领域写，不必套用别人的分类体系；
- 符合规范的分类在侧栏以字母标识；启用「仅扫描规范命名目录」后，第一层只收录这种命名的目录。

工具目录不需要改名，保持原始名称即可。

## 扫描规则

**识别为工具**——目录直接包含下列任一内容：

| 类型 | 内容 |
| --- | --- |
| 启动入口 | `.exe` `.bat` `.cmd` `.lnk` `.ps1` `.py` `.jar` `.js` `.mjs` `.cjs` |
| 工程标记 | `pyproject.toml` `requirements.txt` `package.json` `Cargo.toml` `go.mod` `.git` 等 |

**合集判定**：同一目录下若有多个各自带启动入口的工具子目录，还夹着零散可执行文件，外层会作为可展开的合集分类处理，子工具仍可单独启动。带工程标记的目录，以及大量插件 JAR 配 `lib/` 的应用发行目录，仍保持完整、不被拆开。

**会被跳过**：点开头的项目、`SuperGUI`、`SuperBay`、`node_modules`、`__pycache__`、`venv`、`vendor`；指向工作区外的目录链接不会被扫描。README、笔记和常见元文件不会作为普通文件条目显示。

根目录直属的工具和可启动文件会直接出现在结果里，普通文档不会作为工具展示。新增或移动目录后自动更新，不需要手动设置扫描深度。

## 给 AI 的规划流程

1. **先问清需求**：工具的用途、现有目录、大致数量、常用工作流程、是否需要保留原位置、希望的分类层级。信息不足时先给可调整的初稿，不要停下来反复追问。
2. **按任务或领域分组**：分类少而清晰，优先用用户自己的说法命名。不要照搬安全工具分类，也不要凭空假定用户装了哪些工具。
3. **给出完整方案**：工作区根目录、树形结构、每个分类的用途、层级建议；明确区分「示例占位」与「已有文件」。
4. **落地前确认**：需要实际创建时，先核对路径和现有内容，只创建约定好的目录；移动已有工具前，说明路径、启动命令和配置可能需要检查。
5. **核对扫描结果**：工具项目应保持完整；启用「隐藏无启动项的目录」时，包含可启动子目录的分类仍会显示。

原则只有一条：**建议可以大胆，动手必须谨慎**。移动、覆盖或删除前，先确认具体范围。

## 示例一：设计与素材

```text
D:\DesignTools\                 # 工作区根目录
├── A-01-图像处理\
│   ├── ImageTool\              # 示例工具，保留原有文件
│   │   └── ImageTool.exe
│   └── 批处理脚本\
│       └── convert.py
├── B-02-视频处理\
│   └── VideoTool\
│       └── VideoTool.exe
└── C-03-素材\
    └── 配色参考\
        └── palette.txt
```

`C-03-素材` 里没有启动入口，默认不会出现在结果里；需要时可以在设置中调整是否隐藏这类目录。

## 示例二：小型单层目录

工具不多时，不必强行分层，直接放一层分类即可：

```text
D:\Tools\
├── A-01-常用\
│   ├── 编辑器\
│   └── 截图工具\
├── B-02-脚本\
│   └── 批量重命名\
└── C-03-待整理\
```

后续工具变多，再把分类拆成子目录，SuperBay 会自动跟随。

## 改名与移动

- 笔记写在工具目录内（`NOTE.md` 或已有的 `00.txt`），目录改名或移动后会跟着走。
- 固定、标签、别名、启动命令、运行环境和最近记录按完整路径保存，外部改名或移动后不会自动跟随；旧记录可在「设置 → 工作区 → 维护 → 清理失效记录」中删除。工具文件和笔记不受影响。

## 常见错误

| 做法 | 后果 | 建议 |
| --- | --- | --- |
| 工作区选到某个工具内部 | 只扫描到一个工具 | 选到存放分类的上一层 |
| 脚本直接放在分类目录 | 分类被当成一个工具，脚本混在一起 | 为脚本建一个工具目录 |
| 把一个工具的文件拆到多个目录 | 启动入口与依赖分离，启动失败 | 一个工具一个完整文件夹 |
| 分类嵌套过深 | 侧栏需要反复展开 | 控制在两层以内 |
| 目录改名后期望元数据跟随 | 固定、标签、启动方案丢失 | 重新设置，或清理失效记录 |

行为有疑问时以代码和测试为准：扫描逻辑在 `native/catalog.rs`。
